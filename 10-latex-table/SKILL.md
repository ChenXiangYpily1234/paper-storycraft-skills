# 论文表格设计

> **统领规范**：执行本 Skill 前先读根目录的 `总纲领.md`。所有新出现的表格名词、指标、缩写、分组和统计单位必须在表格附近解释，并与正文及图注的标准术语一致；绝不能为紧凑而牺牲审稿人理解。

## 工作顺序

1. 定位用户指定的 `.tex`、文档类及真实表格，检查项目规则、当前布局和可用栏宽。保存或比较现有数值、标签、引用与结论边界。
2. 说明这张表回答的问题，区分概览表、结果表与消融表。先缩短表达和整理重复信息，再调整列型与间距。
3. 保持各表字号一致，尽量让表头和短数据项单行。修改正文首次介绍和表注，使表格可以读懂且正文不重复。
4. 使用项目构建流程编译，检查 unresolved citations/references、overfull 和浮动结果；渲染并查看所有受影响页，核对数值和 PDF 阅读顺序。

用户指定的内容边界和出版模板优先。只改授权的表格和必要解释，不改变实验值、统计含义、比较对象或论文其他章节。

## 字号与单行布局

- 默认可先考虑表体和表头统一 `\small`；caption 保持文档类统一样式。已有统一字号时优先沿用。
- 表头和短单元格优先单行，用 `l/c/r`。仅在真正需要长描述时采用 `p{}` 等可换行列；概览表不应成为正文段落的复制。
- 先使用简洁但准确的列名，例如 `方法 / 角色 / 核心机制 / 前提`（如论文为英文则采用相应英文标准术语）。缩写、指标和细节在正文或简短表注解释，不能删除单位和统计限定以追求单行。
- `R@10 drop (\%)` 应作为一个完整表头。过长时先缩短相邻列或调整间距；避免滥用 `\mbox` 把整表推到栏外。
- 单栏紧凑表可用 `tabular*{\columnwidth}{@{\extracolsep{\fill}}...@{}}`、`\tabcolsep` 约 2.5–3.5 pt、`\arraystretch` 约 1.05；参数以实际 PDF 为准。
- 使用 booktabs 三线表，避免竖线、满格横线和无意义底色。数值对齐，前导零一致，精度按实验规范统一，不补造有效位数。
- 不用 `\resizebox`、`\scalebox` 或逐表缩小字号强行塞入。仍然过宽时考虑紧凑列名、panel、合理拆表或双栏 `table*`；保留全部关键证据。
- panel 共有的样本数或常量可放在 panel 标题或表注中，但每行变化的量仍须逐行呈现。
- 按信息密度决定是否拆列。若某列仅一两行有值、其余大多为破折号，优先把短限定挂在模型名后，例如 `Qwen3-4B (Label)`，避免为了单行增加空列。多个条件真正独立变化时才拆列。
- panel 共用列含义时保留一套表头；若末列在不同 panel 中分别为 LCB 和 CI，可用 `Bound`，并在表注明确各自的单双侧、置信水平与样本范围。不能以统一列名掩盖不同统计含义。
- 简称只解决扫描问题：`Sup. / NR / 1-shot / Tools / All / Exact` 等必须能从正文或表注明确解码。保留前导零、单位与原精度，不为了省宽度把 `0.092` 改成 `.092`。
- 加粗规则要有统一意义，例如每组最佳值；不能让加粗暗示未经检验的显著性。

## 表注与引用

- 数据集、模型、方法或数据来源在正文首次介绍处引用文献。避免在表体和表注重复引用；用户要求或模型概览表需要保留模型名后的引用时，沿用并检查单行布局。首次讨论表时使用 `Table~\ref{...}`，保留实际存在的 label。
- 表注尽量短，交代对象、指标、panel 与必要统计口径。实验对象和基线在结果表出现前的正文解释；不要用长表注弥补正文缺失。
- 区分均值、worst-seed、LCB 和置信水平。跨 seeds 的判断、无效输出处理与测试范围必须保留，不能在压缩时悄悄移除。
- 明确候选 coverage 与评价分母。例如目标仅对部分用户进入候选池时，说明 R@K 是否仍在所有测试用户上计算、池外用户是否贡献零；valid-output panel 单独说明分母及其对应对照值。
- 角色名称服务论文问题。普通推荐比较可用 baseline；若同一系统也是 recovery formalism 的 target，可写 `primary baseline and audit target`，而不是把全文的 target 一律替换掉。
- 表中的 fixed reference 必须交代确定规则：实验前指定、validation 选择后冻结，或回顾性选择。枚举所有组合的代码不能证明某个报告组合的选择时间；拟合 router/SFT 的 validation 过程也不等于选择 fixed pair。查实现和记录，缺少依据时请求事实确认，不补造选择历史。
- 如果主文删去某个方法，检查是否仍在表格、表注和 conclusion 中出现。补充材料必须有真实结果且处于用户授权范围内，不能编造去向或实验。

## 浮动与视觉验收

- 实际 PDF 的阅读顺序比源码先后更重要。数据表应服务 setup，模型地图在对应比较前出现，结果表不拆断连续的结果段落，诊断图表不拖到 Scope/Conclusion 之后。
- 按观察到的问题局部调整浮动参数或 `\FloatBarrier`。不要在每张表后机械加 barrier；双栏文档可能因此产生空栏或 large underfull vbox。
- 需要严格的“定义 → 表 → 结果”顺序时，先尝试局部放置控制；已有 `float` 包且实际浮动仍拆断语义时，可对该表使用 `[H]`。使用后检查空栏和跨页，不能把 `[H]` 设为所有表的默认值。
- 如需提高版面利用率，先精简表格和正文的重复说明；不得以省空间为目的删去必要定义或证据。用户明确要求保留正文的图表，不能自行移入补充材料。仅当另行提供真实投稿要求时才检查相应版面限制。
- 不为挤表改文档类、页边距或全局正文字号。不要把成功生成 PDF 当作无警告或符合投稿要求。
- 编译后核对全部表的字号、表头换行、表宽、数值、单位、表注、跨页及正文关联；记录新增警告与残留警告。
- 独立 LaTeX 文档默认使用内置编辑器/编译工具；多文件项目优先按项目流程构建。依赖不支持时保留源码，使用已存在的可行构建路径并准确报告。
