# 摘要叙事设计与修订 Skill

## 适用范围与目标

用于修改或从零构建计算机科学及相近技术学科的论文摘要，适用方法论文、实证论文、理论论文、系统论文、数据集与基准论文、复现研究和机制分析论文。目标不是制造戏剧冲突，而是让读者第一次阅读就能说明：**研究问题是什么、为什么需要研究、提出了什么、证据是什么、结论能覆盖哪些范围**。

**通用原则：先确定论文实际贡献类型，再选择叙事模板。** 原文关于“机制是否必要”“性能能否恢复”的框架仅适用于相应研究，不能强制套用于所有论文。不得为增强故事性制造不存在的研究空白、负面结论或定量优势。

## 执行前读取

优先收集题目、引言、方法概述、实验主要表格、关键图、结论、论文实际贡献、现有摘要。若缺少结果数据，不编造数字；标记为“待提供/待核验”。若只提供摘要，仅做可验证的语言与结构修订，并列出需要论文正文核查的主张。

## 1. 提炼摘要的核心故事

先填以下“六问卡片”，再动笔：

| 环节 | 应回答的问题 | 典型错误 |
|---|---|---|
| 背景 | 具体研究对象与任务是什么？ | 宏大空话、术语堆积 |
| 缺口 | 已有方法或证据具体欠缺什么？ | 宣称“无人研究”却未核验 |
| 问题 | 论文真正试图回答什么？ | 把方法名称当研究问题 |
| 解法 | 核心想法与关键区别是什么？ | 罗列模块与缩写 |
| 证据 | 哪个结果最能直接回答问题？ | 堆满数据集和小数 |
| 意义与边界 | 证据支持何种范围内的结论？ | 从相关性推断因果、无条件泛化 |

建议写出一句不含方法缩写的故事主轴，例如：“已有方法在条件 X 下难以解决 Y；我们通过 Z 改变关键限制，并在 A/B 条件下观察到与 Y 直接相关的证据。”该句是写作检验工具，不应机械贴入摘要。

## 2. 按贡献类型选择结构

- **方法或模型论文**：任务与实际瓶颈 → 已有办法为何不足 → 核心机制/建模思路 → 最能区分贡献的实验 → 适用条件。
- **系统论文**：现实需求与运行约束 → 设计挑战 → 系统原则与架构 → 吞吐、延迟、资源或可靠性证据 → 部署边界。
- **理论论文**：问题和假设 → 现有理论缺口 → 定理或算法要点 → 新保证或反例 → 假设限制。
- **数据集/基准论文**：评测盲区或数据缺陷 → 构建原则 → 数据/协议特色 → 验证发现 → 使用限制与风险。
- **机制分析/因果审计**：已有观察不能证明何种机制性主张 → 可区分解释的干预/对照 → 证据 → 条件化结论。
- **负结果/复现论文**：原始主张与复现条件 → 独立复核方式 → 一致或不一致的证据 → 可解释范围。

以上是可选骨架，不是必须写成固定句数、固定设置数或固定长度。摘要的形式与篇幅由作者的实际用途决定，而不是本 Skill 预设。

## 3. 逐层构建信息

### 起句：从具体任务进入

优先说清研究对象、操作或失败现象，再引出问题。避免首句连续定义多个抽象概念，也避免“近年来 X 发展迅猛，受到广泛关注”之类无信息开场。

### 缺口：指出无法由现有证据回答的问题

区分**任务困难**、**方法缺陷**、**证据不足**、**外部有效性未明**。写清成立条件与影响，不以“现有方法全部失败”代替文献判断。若未做系统检索，使用“现有评估尚未充分检验……”等可核查表述。

### 方法：先讲动作与原因，后讲名称

用一至两句概括输入、核心操作、输出及其与缺口的对应关系。复杂机制分解成简短句；首次出现专有名词时给读者一个直接可理解的解释。不要过早介绍损失函数、训练细节和内部组件名。

### 证据：以可对齐的问题为中心

提取能够回答研究问题的关键结果，注明任务、指标、比较对象和必要条件。无需强行挑选某个固定数量的结果，但同一信息不要以不同措辞反复出现。若报告提升，区分相对提升、绝对差值及百分点；“最佳”“最强”“显著”必须有明确范围和统计根据。

### 结尾：回扣研究问题

结尾说明“这些结果表明什么”，而非重复“本文提出了……”。对可能性、必要性、充分性、相关性和因果性作严格区分。对于负面或非显著结果，不把“未能证实 A”写成“证明非 A”。

## 4. 术语、引用与数字纪律

1. 同一实体使用同一标准术语；确有不同概念时不得用同义词混淆。
2. 先介绍通俗含义，再使用缩写。摘要的术语须与题目、引言和图表一致。
3. 数据集名和基线名仅在有辨识价值时写入；否则可使用准确的类别描述。
4. 重要数字必须与正文、图表、统计检验和结论逐项比对；没有来源的数字不可补写。
5. 引用若必须出现，只引用直接支持对应断言的文献；不虚构 citation key、作者或年份。
6. 不把被比较系统的**性能恢复**写成系统本身被恢复；不把独立构造的替代方法写成对目标系统内部机制的替换。
7. 不将局部提升上升为普遍适用性、效率优势或理论保证。

## 5. 典型反模式与修复

| 反模式 | 修复策略 |
|---|---|
| 摘要像术语表 | 先写具体现象，再引入必要定义 |
| 研究空白宽泛 | 指定任务、条件、证据类型或方法边界 |
| 方法句嵌套太多 | 拆开“目标”和“如何实现” |
| 实验像成绩单 | 选能回答核心问题的结果并说清对照 |
| 连续堆数据集/模型名 | 用类型概括，重要例外保留 |
| 主张超出证据 | 增加评价条件与不确定性范围 |
| 结尾重复方法 | 以发现、启示或受限结论闭环 |
| 摘要与全文不一致 | 优先纠正事实/数字，再修改修辞 |

## 6. 实施流程

1. **事实抽取**：建立“主张—证据—位置—可信程度”表。
2. **一句话主轴**：说明论文解决什么难题，避免仅描述做了哪些事。
3. **选择模板**：根据贡献类型确定论证顺序，不强制两种实验设置。
4. **信息排序**：问题优先于自创术语；意义优先于实验流水账。
5. **逐句压缩**：每句增加一种新信息或承担必要衔接。
6. **逆向验证**：检查每个数字、比较词、因果词、术语是否能在正文定位。
7. **跨章节对齐**：与标题、引言首段、结论和主图保持同一故事。

## 7. 必须输出

依次提供：① 当前摘要故事线诊断；② 建议的“问题→缺口→方法→证据→边界”链；③ 修改后的完整摘要（保持稿件使用语言）；④ 关键改动与理由；⑤ 证据待核验清单。若用户只要求审查，可只给诊断和修改建议，不擅自把未经证实的事实写进成稿。

## 8. 质量评估

按以下维度分别评估并提供证据：首次阅读可理解性、科学问题清晰度、方法与缺口对应性、结果可核验性、结论边界、术语一致性、叙事连贯性、信息密度。不要把主观打分当作投稿录用概率。

**最终检验**：不了解论文的研究者能否在读完摘要后回答“为什么做、怎么做、凭什么这样说、在哪些条件下成立”？
